# iPad mini 2 A7 PongoOS and hello-juan MVP

Date: 2026-11-05

## Result

The first complete iPad mini 2 hardware MVP succeeded:

```text
fresh A7 DFU
→ official checkra1n 0.1337.2
→ checkm8
→ download mode
→ embedded PongoOS 2.6.2-3c6a76da
→ USB 05ac:4141
→ hello-juan module load
→ juan help
```

The iPad display remained on the PongoOS terminal after the module loaded.
The host independently confirmed the Pongo USB device:

```text
Bus 001 Device 013: ID 05ac:4141 Apple, Inc. PongoOS USB Device
```

The Pongo USB serial identified the running build as:

```text

```

## Successful host setup

The reliable attempt used:

- the right-side USB port on the MacBook Pro, addressed as root port `1-5`;
- `sudo`, because the Pongo USB node was `root:root` without a user ACL;
- official checkra1n `0.1337.2`;
- the Pongo image embedded in that official checkra1n build;
- `fwupd` stopped during the attempt;
- `apple_mfi_fastcharge` blacklisted and unloaded.

The successful command was:

```bash
cd /home/garassino-juan/Code/007-sandbox/003-pongo-lab
sudo scripts/checkra1n-a7-cue.sh
```

`scripts/checkra1n-a7-cue.sh` now defaults to official checkra1n
`0.1337.2` and its embedded Pongo image. The wrapper also refuses to start if
`fwupd` or `apple_mfi_fastcharge` can interfere with the Apple DFU/Pongo USB
device.

## Module load and exact output

After Pongo appeared as `05ac:4141`, Juan explicitly approved the bounded
module test. The initial unprivileged Python attempt failed before opening the
device with `Errno 13 Access denied`; no module bytes were sent. The approved
commands were then run with `sudo`:

```bash
sudo .venv/bin/python src/pongoOS/scripts/module_load.py \
  build/hello-juan.2.6.2-3c6a76da

sudo .venv/bin/python src/pongoOS/scripts/issue_cmd.py 'juan help'

sudo .venv/bin/python src/pongoOS/scripts/fetch_stdout.py
```

## Pongo USB development access

A narrowly scoped udev rule was installed for the Pongo USB product only:

```text
05ac:4141 → group plugdev, mode 0660
```

It does not grant access to normal iPadOS, DFU, Recovery Mode, or other Apple
USB products. After installing the rule, the previously approved `juan help`
command succeeded without `sudo` through:

```bash
scripts/pongo-command.sh 'juan help'
```

This gives the host a reviewable non-root path for future Pongo shell and
diagnostic work while preserving explicit approval for each hardware-visible
payload or state-changing action.

## Safety record

No restore, downgrade, NAND write, persistent storage write, `bootx`, or
arbitrary memory operation was issued. The only hardware payload loaded after
Pongo was the explicitly approved `hello-juan` module, followed by `juan help`
and a stdout read.

## Lessons learned

- The reliable A7 Linux path is official checkra1n `0.1337.2` running as root
  on the right-side USB root port.
- Overriding checkra1n's embedded Pongo with the `d068ec60` image reached
  `Booting PongoOS...`, but did not produce `05ac:4141`.
- Using the embedded `3c6a76da` Pongo image made the final USB transition
  reliable.
- `fwupd` and `apple_mfi_fastcharge` both raced the exploited Apple USB
  device; stopping/blacklisting them removed host-side interference.
- With this host and `0.1337.2`, no cable action was required after the
  initial fresh DFU entry.
